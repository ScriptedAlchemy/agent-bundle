Let the Workbench App workspace open its bound session from the launches the dev server judges eligible for that server and drive one real call lifecycle through the preview. `GET /api/mcp/launches?epochId=&serverName=` lists `{ launchId, targets }` groups resolved from the artifact's declared projections with installed hosts consulted, and the workspace's **Launch** selector replaces the global-target picker, so a target the build declares but no host can launch is never offered. `POST /api/mcp/apps` now accepts `input` without `result` to mount a preview for a call in flight (`ui/notifications/tool-input` only), and `POST /api/mcp/apps/<binding-id>/result` with `{ result }` or `{ cancelled }` publishes that binding's single terminal notification — `tool-result` (including `isError` results) or `tool-cancelled` — answering `accepted: false` once settled, closed, or when the binding was created with a result. Calling a tool in the workspace mounts the preview immediately, **Cancel call** aborts the in-flight call and cancels the App, and an outcome for a call the workspace no longer shows is dropped rather than delivered to a newer preview (#747, #751)
