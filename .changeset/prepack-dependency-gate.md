Gate `agent-bundle prepack` on the installed-dependency fields of `package.json` so a published plugin installs only what its packed files need: `AB7014` reports a `dependencies`, `optionalDependencies`, or `peerDependencies` entry that no packed JavaScript imports, requires, or resolves, no packed declaration file references, and no `imports` mapping or consumer install script (including scripts it delegates to with `npm run`) reaches — a warning rather than an error for a `peerDependencies` entry, which may be a deliberate host-compatibility contract — (the build inlines every dependency into `dist/bin` and the host packs, so a runtime external must be reached one of those ways; optional peers are skipped), and `AB7015` reports an entry whose name npm rejects or that a consumer's npm cannot resolve through a registry: git, a GitHub shorthand, a remote tarball, a path or bare tarball filename, or a scheme npm cannot parse (`link:`, `portal:`, a typo — reported even on an optional peer, since `EUNSUPPORTEDPROTOCOL` fails the install before any fetch), which npm 12 refuses to fetch by default (`allow-git`, `allow-remote`), and `workspace:`/`catalog:` unless pnpm, Yarn, or Bun is running the pack and will rewrite them; a scheme-less selector must be a semver range or a URL-safe dist-tag; an `optionalDependencies` entry npm parses but cannot fetch warns rather than fails, since npm continues without it (one npm cannot parse stays an error) — `agent-bundle prepack` prints such warnings and exits 0, and `prepack()` returns them on `PrepackResult.diagnostics`. Emitted `INSTALL.md` files now state that the bundle is self-contained, use the host's own `claude plugin` / `codex plugin` commands for uninstall, and mark every `agent-bundle install`/`uninstall`/`doctor` mention as optional automation. The `create-agent-bundle` `mcp-server` and `cli-tool` templates declare `@agent-bundle/runtime`, `react`, and `zod` under `devDependencies`. (#547)
